# 多腕バンディット実装：読解ガイド

**目的**：シミュレーションの問題設定、数式、データ構造、学習処理、評価指標の対応を整理する。数式の詳細は[理論・導出ノート](theory-and-derivations.md)、発表の分析は[発表レポート](presentation-analysis.md)を参照。

## 最初に理解する問題設定

10本の腕のうち、1本だけ成功確率が高い。学習者はその腕を知らず、報酬を観測しながら選ぶ。現行実装は成功確率が良い腕0.65／通常腕0.44、成功で+1／失敗で−1、初期予算20、最大100ステップ。予算0で終了する。

成功確率を $p$ とすれば期待報酬は $2p-1$ なので、良い腕は+0.30、通常腕は−0.12。

**注意**：発表スライドで扱った基本モデルは成功確率0.70／0.40、最大1,000ステップなど別条件。現行実装の実験結果と混同しないこと。

## NumPy配列の意味

| 変数 | 標準設定でのshape | 意味 |
| --- | --- | --- |
| good_arms | (5000,) | 各独立試行の良い腕の番号 |
| q_values | (5000,10) | 各試行が保持する10本の腕の推定価値 |
| wealth / alive | (5000,) | 各試行の所持予算／継続状態 |
| budget_paths | (5000,101) | 各試行の時刻0〜100の予算 |
| expected_budget_path | (101,) | 各時刻について5000試行を平均した予算 |

**行方向**に5,000回の独立試行をベクトル化して処理し、**時間方向**には更新したQ値が次の行動を決めるため順番に進める。5,000件がQ値を共有するわけではない。

**active** は破産していない試行の行番号。例えば alive = [True, False, True] なら active = [0, 2]。破産者は次の行動から除かれるが、予算0で平均に含まれる。

## 学習の中心：ε-greedyとQ値更新

ε-greedyは、確率 $1-\varepsilon$ で現在のQ値が最大の腕を選び、確率 $\varepsilon$ で**全K腕からランダムに**選ぶ。探索時にも最良推定の腕を選ぶ可能性がある。

観測報酬 $R$ を使い、選んだ腕のQ値を更新する。

$$
Q_{\mathrm{new}}(a)=Q_{\mathrm{old}}(a)+\alpha(R-Q_{\mathrm{old}}(a)).
$$

**手計算**：初期Q=0、学習率 $\alpha=0.2$ で成功（+1）するとQ=0.2。同じ腕で次に失敗（−1）するとQ = 0.2 + 0.2(−1 − 0.2) = **−0.04**。

**NumPyの重要箇所**：q_values[active, actions] は、activeとactionsの同じ位置の組から要素を取る。active=[0,2]、actions=[1,3] なら「試行0・腕1」と「試行2・腕3」を指し、行×列の全組み合わせではない。

## 実験と解釈

現行の[experiment.py](../experiment.py)は、学習率 $\alpha=\{0.05,0.20,0.80\}$ と探索率 $\varepsilon=\{0.02,0.10,0.40\}$ の9条件について、各5,000件を実行する。

- **最終予算期待値**：破産した試行を0として含めた最終予算の標本平均。
- **破産率**：全試行に対して予算が0になった試行の割合。
- **良い腕の選択率**：各独立試行で選択率を計算し、その値を試行間で平均。
- **平均累積報酬**：最終予算期待値 − 初期予算。

[実験結果CSV](../results/summary.csv)における最良条件は、比較した9条件のうち **α=0.05、ε=0.02**（最終予算平均25.2536、破産率9.26%、良い腕選択率約40.57%）。

**「9条件内で最高」以上の主張はできない**。比較の乱数誤差、未検証のパラメータ領域、ベースラインや信頼区間の欠如に注意する。

## 動作確認と結果の保護

リポジトリのルートから以下のコマンドを実行する。

    python -m pip install -r requirements-dev.txt
    python -m pytest -q
    python multi-armed-bandit/experiment.py --n-runs 100 --output /tmp/bandit-preview
    python multi-armed-bandit/experiment.py --n-runs 5000 --output /tmp/bandit-reproduction

軽量実行も完全実行も **--output** で別の保存先を指定しておくと、コミット済みの results/ を不用意に上書きせずに済む。

## 実装理解の確認項目

1. 真の期待報酬と学習者のQ値の違いは何か。
2. 探索率εが0.1なら、どのように行動を選択するか。
3. 学習率αが大きいと、Q値のノイズと反応速度はどう変わるか。
4. なぜq_valuesは5000×10配列で、時間方向はforループなのか。
5. 破産した試行は予算の平均から除外されるか。
6. なぜ「最良パラメータ」を一般的な最適値と言い切れないか。
7. 発表スライドと現在のGitHubの結果を直接比較できない理由は何か。
